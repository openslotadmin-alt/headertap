HeaderTap help

HeaderTap adds, changes or removes HTTP request and response headers on the sites you choose. It runs on Chrome's own rule engine. There's no account, no tracking, and it makes no network requests. See the privacy policy.

Getting started

  • Click the HeaderTap icon in Chrome's toolbar. (If it isn't there, click the puzzle-piece icon and pin HeaderTap.)
  • Under Request headers, type a header name and value, for example X-Debug and 1.
  • Click Allow on the site you are on. Chrome asks you to confirm. HeaderTap changes headers only on sites you allow.
  • Reload the page. The Checks panel shows the changes in force and how many of this tab's requests they applied to.

For more room, click Full editor to open HeaderTap in a tab.

Profiles

A profile is a set of headers plus where they apply. Keep as many as you like, for example "Staging API", "Mobile UA" and "No cache", and turn each on or off. When two profiles set the same header, the one listed first wins. Use the arrows to reorder them. Pause all turns everything off at once, and the toolbar badge then reads "off".

Set, Append, Remove

  • Set replaces the header's value, or adds the header if it is missing.
  • Append adds your value to the existing one. Chrome allows this only for certain request headers, such as Accept-Language, Cookie, Cache-Control and User-Agent. HeaderTap tells you when a header isn't one of them. Response headers can always be appended.
  • Remove takes the header out.

Apply to: filters

With no filter, a profile applies on every site you have allowed. Add filters to narrow it:

  • Domain: api.example.com covers that domain and its subdomains.
  • URL filter: Chrome's pattern syntax, for example ||example.com/api/ or /graphql.
  • Regex: a regular expression matched against the full URL.
  • Not + domain leaves that domain alone.

Site access, and why both sites matter

HeaderTap installs with access to no site. Chrome only changes a request when HeaderTap is allowed on both the request's site and the page that sends it. So if your app at app.example.com calls api.example.net, allow both. The Site access panel lists the sites a profile's filters name that aren't allowed yet, each with an Allow button. You can remove access there at any time. Allow all sites is there if you want it, behind Chrome's own prompt.

Importing from ModHeader

In ModHeader, export your profiles as JSON and copy the text, or save the file. In HeaderTap, click Import, paste the text or choose the file, and click Check. HeaderTap shows how many profiles, headers and filters it found and imported, and lists anything it couldn't bring across, with the reason. Then click Add profiles. HeaderTap reads the file in your browser and never uploads it. It doesn't open ModHeader share links (those need a network call); paste the JSON instead.

HeaderTap is not affiliated with ModHeader. The name is used only to say which export format it reads.

When a header doesn't seem to change

  • Is the profile on, with no ✗ in the Checks panel?
  • Is the site allowed, and so is the page making the request?
  • Did you reload after changing something? Requests already sent aren't changed.
  • Responses that a page's own service worker serves from its cache aren't changed by any extension's rules.
  • Chrome's developer tools show some headers as they were before extensions changed them. To be sure, check what your server received.
